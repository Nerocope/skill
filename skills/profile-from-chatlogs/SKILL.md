# 从聊天记录读懂一个人（Profile from Chatlogs）

用**任意聊天/对话资料**（DeepSeek 等 AI 对话导出、微信记录、Telegram、邮件、日记）对目标人物做**基于证据的人本主义解读**。产出物是一篇**连续长文**（约 1 万字），以"读懂了一个人"的口吻书写，每条引文可点击回溯到原始对话。

## 什么时候用

- 用户提供聊天记录（JSON/文本/截图），要求分析"我/某个人"的性格、心理、处境
- 用户说"从这些记录里看我是谁""读懂我""给我写个人物画像"
- 用户已有报告但嫌弃太冷/太演，要一篇"人读人"的解读

## 触发后第一件事：确认需求形态

先用最多 4 个问题**拷问需求**，不要直接开写。必须问清：

1. **"被读懂"的定义**：照镜子（如实还原）／捅破（指出没看到的）／帮做决定（下一步）／还没想清楚
2. **命中瞬间**：被原句击中／被模式揭穿／被平实但深的话打动／被直接指路
3. **读法**：一段长文读完／一条条盲盒式揭晓／先给结论再挑着重看
4. **揭穿分寸**：大胆写（拿不准一句带过）／保守稳（只写铁证）／大胆但留证据尾巴

用户最常见的真实答案组合：**"被平实但深的话打动" + "一段长文读完" + "大胆写，拿不准一句话带过" + "先帮我想清楚要什么"**。这个组合意味着：连续长文、语气平实但深、不术语不煽情、把用户自己没意识到的细节端出来、大判断要有原句支撑、拿不准的明说。

## 核心原则（血的教训）

1. **语境必须是完整的**：只看用户单方的话会失真。必须恢复"用户提问 + AI 回复"的完整回合序列，心理推断要放进回合语境里。
2. **区分"自己说的"和"粘贴的"**：聊天记录里常混着用户**复制进来的别人的话**——名人名言（如罗永浩语录）、征友简介、他人发来的消息、转载段落。这些**绝不能当成用户本人的自述**去写。判定标准：只有以**第一人称、亲口说出**、语境上确属自述的内容才作数。拿不准宁可删，不要冒充。
3. **引文必须可回溯**：每条引用都要能指回原始对话（卷号/会话编号/位置）。引文标注日期或出处。**禁止编造"大意"**——你没抓到的原话，宁可写转述也不写引号。
4. **不写"核对区/附录"式的割裂尾巴**：长文正文必须连续。粘贴材料的说明、证据表格等，融入正文一两句带过，不要另起独立区块。
5. **保持人对人的口吻，不要"老人/长辈"式表演**：用户会立刻识别出表演性的共情。要的是平实的深，不是戏。
6. **不把引用当成表演**："一位老人读懂了你的聊天记录"这种口吻若用户不认可，立即撤掉，回到平实。
7. **大胆写但标出不确定**：大判断给足证据；拿不准的（如无法确认身份的片段）用一句"这里我拿不准"带过，不打断阅读，也不两头下注。

## 工作流程

### 第 1 步：资料预处理与恢复回合

- 解析原始数据（JSON 导出通常有 mapping/树结构：REQUEST=用户，RESPONSE=AI，FILE=附件）
- 按会话把碎片恢复成完整回合序列，合并连续同一说话方
- 标记每个会话的时间

### 第 2 步：分区分卷（解决长文本装不下的问题）

- 按时间把全量对话切成 3~4 个区域（如：2025H1 / 2025H2 / 2026 / 当前）
- 用主题词表 + 权重给会话分类（心理情感类权重最高），**高价值会话**（个人表达强：关系/内心主题，或情绪词/第一人称密集）抽出来单独成"key 卷"整读
- 全量会话生成**索引**（会话 id + 时间 + 主题 + 价值标记），供检索与追溯
- 单卷体积控制在 12 万字符以内（约 1 字≈1 token，保证单卷装得进窗口且留出 AI 输出空间）；超大单个会话按行拆
- 并行读取时**最多同时 3 个子代理**（受平台约束），采用流水线：一批完成后立即补新

### 第 3 步：逐卷精读 + 结构化笔记

每个子代理按统一 schema 读一卷 key 卷，产出笔记：
- 会话清单（id、时间、主题）
- 逐会话要点：**直接引用原句**（不转述大意）、行为模式、对 AI 的回应模式
- 卷级总结：该时期的核心主题、情绪走向、与前后期的连续/断裂

### 第 4 步：二级合并 + 交叉验证

- 合并各卷笔记，找出**跨时期反复出现的模式**（例如"极度渴望亲密 vs 主动推远对方""只在付出时才感到有价值 vs 痛恨被当成工具"这类成对出现的内在矛盾结构）
- 做全量统计交叉验证（情绪词密度、第一人称代词频率、回应模式分布、时间轴变化）
- 关键大判断必须有原句支撑，归入笔记供最终引用

### 第 5 步：写长文（约 1 万字）

结构建议（都融入正文，不设割裂区块）：
- 开头：说明"我是怎么读的"（读了什么、怎么读），建立信任
- 核心矛盾：2~4 个最重要的内在结构（例：渴望被无条件看见 vs 恐惧被需要；能力极度自信 vs 自我评价极度苛刻）
- 具体证据：每条引文标注日期，可点击跳回原卷
- 时间线：讲"这一路怎么走过来的"（按时期叙述，注意身体、职业、关系的交互）
- 模式总结：把用户自己没意识到的细节端出来（跨对话才能浮现的隐性行为模式，单看一段看不出来、合起来才成立的那种）
- 结尾：不给"你要振作"式的场面话；给确凿的观察；把不确定的用一句话交代
- **注意**：所有引号内的内容必须是原话；引用外部粘贴材料时要声明"这是转述的别人的话，不作数"

### 第 6 步：交付与修正

- 交付为单个 HTML 文件（长文阅读体验，引文可点击跳原卷）
- 主动指出引文中哪些是"我核过的原话"、哪些是"子代理转记、需要你确认"的，请用户核对
- 用户指出的归因错误、格式问题，逐条改

## 引文归因审核（关键步骤）

正式成文前，必须对每句引文做**归因审核**：
- 从原始 JSON 中定位每个引文关键词命中的会话，抽出命中处上下若干**完整回合**
- 判断：这是用户第一人称自述？还是转述他人？还是粘贴的第三方材料？
- 标出每句引文对应的原始卷/会话，供链接
- 处理规则：粘贴的别人话 → 不作数、不据此下结论；转述 → 说明是"她/他说我"；拿不准 → 标注待确认或删

## 常见坑

- ❌ 只看用户单方文本 → 语境失真（必须先恢复回合）
- ❌ 把用户粘贴的名人名言/征友简介当本人自述 → 重大归因错误
- ❌ 编造"大意"引文 → 违反证据原则
- ❌ 加"核对区/说明区"独立区块 → 割裂长文阅读
- ❌ 表演性口吻（老人、大师、心理医生腔）→ 用户反感
- ❌ 超 3 个并发子代理 → 违反平台约束
- ❌ 单卷超 12 万字符 → 窗口装不下，被压缩丢失信息

## 示例

**触发**："这是我的微信聊天记录导出，帮我分析一下我是谁。"

**第一步先问**："你想被读懂成什么样——照镜子如实还原、捅破你自己没看到的、还是帮你做决定？" 然后按第 1 步确认读法和分寸，再进入工作流。

**交付示例**：一篇连贯长文，开头先交代"我读的是什么、怎么读的"建立信任；中段按"核心矛盾 → 原句证据 → 时间线 → 隐性模式"推进，每句引文带日期可点回原文；结尾给确凿观察而非励志口号，不加任何总结框或核对区。
